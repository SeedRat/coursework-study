# 作答读回与提交核对

用于选择、填空、代码或附件已经写入页面之后，以及最终提交之前。

## 最小任务记录

批量任务在当前会话或私有工作文件中保留：作业标题、题号、预期答案/最终代码位置、页面实际内容、验证状态、提交结果、尚缺材料。记录服务于断点续作；不保存带登录令牌的链接或会话凭据。简单单题无需建立额外系统。

多份作业、长测试或可能中断时使用一个精简的本地状态文件，按作业保存题号、预期答案、最近读回结果/差异、代码文件与版本、验证状态、提交结果、剩余材料和下一步。正常核对用简短标记，错误保留必要反馈；题目原文、完整代码和截图分文件引用，不重复嵌入状态记录。可按以下形式记录：

`作业 | 题号 | 预期答案/文件版本 | 最近读回 | 验证 | 提交结果 | 下一步`

每题核对完成、提交结果明确或出现阻塞时更新相关记录，不逐次记录鼠标动作。恢复时先读状态文件及当前所需题目，再现场确认活动作业和最后提交状态；无需重读全部聊天或整个课程。临时工作状态不是学习资料，“无需学习资料”仍可保留必要进度文件；不将这些私有状态、截图或答案打入 Skill 分享包。

## 写入后读回

| 类型 | 必须核实的实际页面内容 |
|---|---|
| 选择/判断 | 题号、实际选中标记、选项字母及对应文字与预期一致；多选核对完整集合 |
| 填空 | 每个空的位置和值、顺序、单位、符号及精度 |
| 编程 | 编辑器最终内容与预期一致；头文件、main、输入输出、末尾完整；运行反馈对应当前版本 |
| 图片/文件 | 上传完成，附件数量及预览正确；需要时核对姓名、学号、文件名、代码与运行结果是否清晰完整 |

代码模板与示例中的输出字符串应尽可能直接提取，保留标点、空格、换行。评测提示格式差异时，先比较已知字符串；编译器提示缺少 main 时，先读回编辑器，检查是否仍是模板或输入落错位置。

## 最终提交前

1. 按全部题号逐题比对预期与实际答案，发现差异则修正并再次读回。答题卡颜色只用于找漏答，不能证明答案正确。
2. 确认所有编程题反馈对应最终代码；运行后再次编辑的题目需要重新验证。最终代码未改变且已验证通过的题目无需重复运行。
3. 检查附件预览和题目特别要求，确认没有未保存修改或尚在上传的文件。
4. 全部目标题目核对完成后提交；确认页若提示漏答，返回定位问题后再提交。

## 提交后

以结果页的分数或“提交成功、待批阅”为完成证据。结果不明时先检查提交状态，避免重复提交。非满分按 Skill 的评分规则处理；操作失误应说明实际错误、成绩及能否修正，不归因于未经证实的用户干扰。

恢复中断任务时先检查网站当前状态，核对最后一题和最后一次提交，再续作；历史截图和记录不替代现场状态。
